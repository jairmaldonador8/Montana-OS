🏢 Montana OS - Sistema de Roles y Autenticación

1️⃣ Estructura de Roles

👤 Asesor (Agent)
Correo: nombre@montana.com
Acceso: Dashboard personal del CRM
Ver: Solo sus propias propiedades
Hacer: Crear, editar, enviar propiedades para revisión
No ver: Propiedades de otros asesores
👨‍💼 Jefe + Secretaria (Admin Staff)
Correo: jefe@montana.com / secretaria@montana.com
Acceso: Dashboard de administración
Ver: TODAS las propiedades de todos los asesores
Hacer: Revisar, aprobar/rechazar, asignar a broker, cambiar estado
Filtros: Por asesor, estado, tipo de propiedad

2️⃣ Flujo de Autenticación

┌─────────────────────────────────────────────────────────────┐ │ INICIO DE SESIÓN │ └─────────────────────────────────────────────────────────────┘ ↓ ✉️ Ingresa: email@montana.com ↓ ┌─────────────────────────────────────┐ │ Validar email en tabla USUARIOS │ └─────────────────────────────────────┘ ↓ ┌──────────────────────────────────────────┐ │ ¿Email está en sistema? + tiene rol? │ └──────────────────────────────────────────┘ ↙ ↘ SÍ NO ↓ ↓ ┌─────────────────────┐ ❌ Rechazar │ Obtener ROL │ (Email no existe) └─────────────────────┘ ↓ ┌─────────────────────────────────┐ │ ¿Rol = agent? │ └─────────────────────────────────┘ ↙ ↘ SÍ NO (admin/jefe/secretaria) ↓ ↓ 🔑 Login 🔑 Login Redirige a Redirige a /propiedades/nueva /propiedades (CRM Asesor) (Admin Dashboard)

3️⃣ Dashboard - Vista del Asesor

URL: /propiedades/nueva
Componentes:
📋 Formulario de nueva propiedad (4 pasos)
📊 Mis propiedades (estado actual)
⏳ Historial y cambios de estado
💬 Feedback de revisión (si fue rechazada)
Datos que ve: Solo sus propias propiedades
Permisos: Crear, editar draft, enviar para revisión

4️⃣ Dashboard - Vista del Administrador (Jefe/Secretaria)

URL: /propiedades (cuando es admin)
Componentes principales:
🔍 Cola de revisión - Todas las propiedades pendientes
📁 Filtros avanzados (asesor, estado, tipo, fecha)
✅ Acciones: Aprobar, rechazar (con comentario), asignar broker
📊 Estadísticas generales (propiedades por asesor, estados)

5️⃣ Flujo de Estados de Propiedades

┌──────────────────────────────────────────────────────────────┐ │ ASESOR crea propiedad │ │ Estado inicial: DRAFT (borrador) │ └──────────────────────────────────────────────────────────────┘ ↓ ┌───────────────────────────────────┐ │ ASESOR: "Enviar para revisión" │ │ Estado → PENDING_REVIEW │ └───────────────────────────────────┘ ↓ ┌───────────────────────────────────────────────┐ │ ADMIN ve en "Cola de revisión" │ │ Opciones: Aprobar / Rechazar / Asignar broker │ └───────────────────────────────────────────────┘ ↙ ↘ RECHAZADA APROBADA ↓ ↓ Estado: REJECTED Estado: APPROVED (vuelve al asesor) (lista para publicar) ↓ ┌──────────────────────────┐ │ PUBLISHER: Publica │ │ Estado: PUBLISHED │ └──────────────────────────┘

6️⃣ Estructura de Base de Datos - Tabla USUARIOS

Campo Tipo Descripción
id UUID PK (vinculado a auth.users)
email text nombre@montana.com
rol enum agent | admin | jefe | secretaria
nombre text Nombre completo
activo boolean ¿Puede acceder al sistema?
creado_en timestamp Fecha de creación

7️⃣ Permisos en la Base de Datos (Row Level Security)

Asesor (agent): Ve/edita solo propiedades donde user_id = su ID
Admin/Jefe/Secretaria: Ve todas las propiedades, puede cambiar estado
Publisher: Ve propiedades aprobadas, puede publicar

8️⃣ Flujo de Creación de Usuarios (Admin)

ADMIN crea nuevo asesor: 1. Nombre: "María López" 2. Email: maria.lopez@montana.com 3. Rol: agent 4. ✓ Sistema genera password temporal 5. ✓ Envía email con link de acceso 6. ✓ María puede resetear password en primer login
